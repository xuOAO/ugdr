## Delivered

- Extracted the stable Worker-facing `CopyBackend` contract and added the production
  `ugdr_cuda_backend` target without adding a reverse Worker dependency to the Client-facing
  `ugdr_gpu` library.
- Added `PersistentCudaCopyBackend`, fixed to the selected single-CTA
  `warp_specialized_pipeline` instance: one ingress warp, 30 copy warps, one egress warp,
  device batch 16, per-copy-warp shared queue depth 16, and 38,400 B static shared memory.
- Added a power-of-two Host task-context ring, target Host batch 64, and a finite 50 us tail
  trigger. Partial publication preserves order and backpressure does not drop accepted tasks.
- Added A10 GPUDirect RDMA capability discovery and
  `cuFlushGPUDirectRDMAWrites(CURRENT_CTX, TO_OWNER)`. Recorder tests establish
  source-ready → completed Host flush → release-publication, and flush failure prevents task
  publication.
- Added accepting → draining → stopped lifecycle handling. Invalid requests, visibility errors,
  queue/kernel errors, and successful device completions all reach one terminal
  `BackendCompletion`.
- Replaced the F05 integration-test Mock backend with the real CUDA backend while preserving the
  Loop Worker as the parent-WR completion authority.
- Added deterministic coverage for aligned 8 KiB LD/ST128 copies, unaligned 8,191 B narrow
  fallback and guards, Host tail batches, queue backpressure, ordinary Write, Write With
  Immediate, multiple SGEs, signaled/unsignaled completion behavior, and resource cleanup.
- Added `ugdr_persistent_cuda_backend_benchmark`. Its measured path is
  post → SQ → requester/responder Loop Worker → 8 KiB payload tasks → persistent CUDA kernel →
  payload completions → one parent response. It performs no `cudaMemcpy` or synchronous CUDA
  copy in the timed interval.
- Closed the formatting debt recorded by F06-S02 for the persistent-copy source/header/test and
  annotated two intentional moved-from contract checks, allowing the complete repository format
  and clang-tidy gates to pass.

## Deviations and Remaining

- No reviewed F06-S03 behavioral deviation was introduced.
- F06 does not implement a real NIC. The integration treats a Local Transport-delivered request as
  the source-ready boundary, tests the required flush-before-publication order, and exercises the
  real A10 Host flush API. A future NIC transport must invoke the same gate only after consuming
  the corresponding NIC completion.
- The benchmark uses an in-process CUDA mapping backend so Client and daemon device virtual
  addresses are identical. Cross-process CUDA IPC mapping correctness remains covered separately;
  the no-key-path-Mock public API composition belongs to F07.
- Payload setup and final correctness verification are deliberately outside the persistent-kernel
  measurement interval. A synchronous CUDA operation in the same context must not be issued while
  this non-preempted persistent kernel is active; callers must prepare before `start` and verify or
  otherwise synchronize after `wait`.
- The selected model remains limited to one CTA and inherits the F06-S02 small-payload trade-off.
  The end-to-end result is materially below the isolated copy-core result because it also includes
  posting, two Loop Workers, parent aggregation, Host batching/flush, and response handling.
- Human implementation acceptance and the Feishu `已实现` checkbox remain pending. This record
  intentionally contains no Acceptance section.
