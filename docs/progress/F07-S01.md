## Delivered

- Added the official daemon data service composition around `QpService`, `LocalTransport`, two
  role-specific `LoopWorker` instances, the CUDA IPC memory backend, and the default Persistent
  CUDA Copy Backend. QP discovery follows controlled session/QP peer relationships rather than a
  fixed QPN scan.
- Added bounded daemon data progress and lifecycle handling. Backend shutdown drains completions
  before releasing workers or CUDA IPC mappings; MR deregistration stops the persistent kernel
  before closing a mapping and permits a subsequent registration to restart the backend.
- Kept the control-only daemon usable without a GPU, while formal CUDA callers can request a
  deterministic skip when CUDA IPC is unavailable. The production default tail-batch delay is
  50,000 ns and remains configurable for the benchmark.
- Aligned Write With Immediate without a posted Receive WR to standard RNR behavior: the remote
  target is not modified and the requester receives an error WC even for an unsignaled WR.
- Added `ugdr_public_api_cuda_acceptance`, which launches the official daemon and two independent
  Client processes. Both clients use only the public API for device/context, PD, MR, CQ, QP,
  connect, post, poll, and child-first teardown operations.
- The acceptance matrix covers invalid pre-RTS posting, signaled Write, unsignaled Write, plain
  Write receive preservation, Write With Immediate and receive consumption, RNR, invalid rkey,
  out-of-bounds remote access, stale rkey after deregistration, re-registration key change, WC
  fields, full-target sentinels/guards, and clean daemon drain.
- Persistent mode of `ugdr_client_daemon_cuda_benchmark` now launches the official daemon. The
  cuda-batch comparison continues to use its existing private service and remains optional.
- Added the daemon-to-CUDA-backend production dependency to the machine boundary policy and kept
  the generated repository skeleton section synchronized.
