## Delivered

- Added the common `CopyTask`/`CopyCompletion` contract, mapped pinned Host memory owner, fixed stage-buffer-relative source addressing, payload correctness oracle, lifecycle shell, result schema, and static model dispatch.
- Added the `.cg` copy core: a 128-bit aligned body and safe 1/2/4/8-byte narrow fallback without reading or writing outside the task range. The candidate path contains no `cp.async`, `cudaMemcpy` benchmark, L2-bypass variant, or cache-policy matrix.
- Added four reviewed physical models:
  - `direct_atomic`: one external task/completion pair with system-scope SPMC/MPSC atomics;
  - `dynamic_sharded_spsc`: one task/completion SPSC pair per copy warp;
  - `static_partition_spsc`: one Host-visible ordered pair with `index % copy_warps` ownership and intentional head-of-line blocking;
  - `warp_specialized`: one external SPSC pair and one CTA with ingress/copy/egress warps.
- Added an additional `warp_specialized_pipeline` experiment using block-scope CUDA barriers and per-copy-warp static shared-memory pipelines. It remains an experimental variant rather than a fifth reviewed model.
- Added compile-time specializations for copy-warp count, device batch, shared queue depth, and static shared-memory storage.
- Added a unified matrix that buffers all result rows until every model has passed deterministic correctness and fairness checks. Result schema version `4` records payload, capacities, Host/device batch, copy warps, shared queue depth, warmup, iterations, ring/meta/atomic counts, MTask/s, GB/s, P50/P99, Host CPU, registers, shared memory, occupancy, and conservation fields.
- Added explicit CLI inputs for long measurement windows and shared queue depths so the T08 run can reproduce both the common matrix and model-specific depth scans.

### Warp and shared-depth scan

- All models scaled through 32 total CTA warps. At Host batch 64, the best 8 KiB core-sweep results at 4/8/16/32 total warps were:
  - dynamic SPSC: 8.12 / 15.66 / 29.08 / 37.12 GB/s;
  - static SPSC: 9.55 / 18.22 / 32.40 / 36.81 GB/s;
  - pipeline: 4.85 / 13.78 / 29.40 / 37.33 GB/s.
- Atomic warp specialization is sensitive to shared depth. With 30 copy warps, depth 32/batch 16 produced only about 18.5 GB/s, while depth 256/batch 16 produced a stable 33.4 GB/s using 20,544 B shared memory. Depth 512 did not provide a stable advantage and doubled shared memory to 41,024 B.
- The pipeline result is sensitive to device batch rather than deeper queues. With 30 copy warps, depth 16/batch 16 produced a stable 37.3 GB/s using 38,400 B shared memory; depth 8/batch 8 was about 25.3–25.7 GB/s.
- For both specialized variants, 30 copy warps plus ingress/egress (32 total CTA warps) outperformed the 14-copy-warp (16 total) configurations at 8 KiB.

### Queue and maintenance trade-offs

| Model | Host-visible queues | Host knows warp count | Main evidence-backed trade-off |
|-|-:|-|-|
| direct atomic | 2 | No | Simple layout, but system atomics and lower throughput/tail latency. |
| dynamic sharded SPSC | 64 at 32 copy warps | Yes | Best small-task rate and near-best 8 KiB result; highest Host scheduling/ring complexity. |
| static partition SPSC | 2 | No | Simple Host boundary and strong small/medium payload result; intentional global head-of-line blocking. |
| warp-specialized atomic | 2 | No | Simple external boundary, but single CTA, depth-sensitive tuning, more registers, and below-leading throughput. |
| warp-specialized pipeline | 2 | No | Best stable 8 KiB result and low register count; single CTA, 38.4 KiB shared memory, barrier/pipeline complexity, and weaker small-task rate. |

### Human model selection

On 2026-07-30, the user selected the pipeline design for the F06-S02 handoff:

| Parameter | Selected value |
|-|-|
| Model | `warp_specialized_pipeline` |
| CTA layout | 30 copy warps plus one ingress warp and one egress warp, 32 total warps |
| Device batch | 16 tasks per copy-warp pipeline stage |
| Shared queue depth | 16 stages per copy warp |
| Host batch | 64 tasks |
| External queue boundary | One task SPSC ring and one completion SPSC ring; Host is unaware of the copy-warp count |
| Launch scope | One persistent CTA |

This selection prioritizes the reviewed 8 KiB workload and the simple Host-visible SPSC boundary. Its five-run Host-batch-64 median was 37.332 GB/s and 4.557 MTask/s, with 35 registers/thread, 38,400 B static shared memory, and 0.667 measured occupancy. The selection explicitly accepts the single-CTA limit and the weaker small-payload task rate. F06-S03 must keep a time/availability threshold in addition to the target Host batch of 64, and on this A10 it must complete the required GPUDirect RDMA Host flush before release-publishing the affected tasks.

### GPUDirect RDMA visibility

A CUDA Driver API probe on the same A10 reported:

```text
gdr_supported=1 writes_ordering=0 flush_options=1
host_flush=1 memops_flush=0
iterations=10000 average_ns=657.892 p50_ns=612.000 p99_ns=622.000
```

`writes_ordering=0` means native ordering is `NONE`; Host flush is supported and stream-memops flush is not. With no pending RDMA writes, the measured Host API lower bound amortizes to approximately 20.6 ns/task at batch 32 and 10.3 ns/task at batch 64. This is not a NIC-path measurement. F06-S03 must flush after consuming the corresponding NIC completions and before release-publishing tasks.

## Deviations and Remaining

- No reviewed F06-S02 behavioral deviation was introduced. The pipeline candidate is explicitly retained as an additional experimental variant and is not silently counted as a fifth reviewed model.
- The experiment uses mapped pinned Host memory and a synthetic ready stage buffer. It does not include NIC DMA, NIC CQ polling, `cuFlushGPUDirectRDMAWrites` in the measured copy path, or F05 parent-WR end-to-end processing; those remain F06-S03 work.
- P50/P99 cover Host submission to Host completion observation. Completion timestamps are sampled once per Host batch to limit instrumentation cost. Host CPU reflects one pinned busy-polling process core.
- GPU application clocks were not locked and persistence mode was disabled. Long warmup and five stable repeats reduce, but do not eliminate, clock/thermal variability.
- `tools/ugdr format --check` reports that the persistent-copy CUDA/header/integration files accumulated before T08 are not globally canonical under `.clang-format`. The T08 benchmark changes are formatted and all required builds/tests/governance checks pass. Reformatting the full historical files here would mix thousands of non-semantic lines into the selection evidence commit, so that cleanup remains explicit follow-up work.
- The model and key parameters were backwritten into F06 feature-document revision `45` and re-reviewed. The remaining NIC integration, real flush path, parent-WR end-to-end flow, and documented formatting cleanup are outside this completed S02 scope.
